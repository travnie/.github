WAM Bridge is a Windows-first Python bridge that lets you stream audio from your PC to Samsung Wireless Audio Multiroom speakers over Wi-Fi. It supports two paths: a command-line tool that serves a tokenized local stream via Samsung's `SetUrlPlayback` API, and a foobar2000 output component that routes whatever foobar is playing (including internet radio) directly to your speaker.

Everything here was measured against a physical SPK-WAM550 running firmware `WAM550WWB-3117.1`. Other models in the Samsung WAM family are untested.

<Warning>
  WAM Bridge is alpha software built by one person against one speaker. The CLI has hardware validation, but the later foobar2000 full-track recheck did not reproduce the older stability results. Read the test status and limitations before installing.
</Warning>

## The latency note

The last measured end-to-end FLAC latency was 6.7 seconds (historical figure, measured before the host buffer was reduced). With `buffer_extra=0`, the host queue is approximately 1.9 seconds. A fresh ear-to-clock measurement has not been taken yet, so the 6.7 s figure is outdated rather than current.

Earlier clean runs showed a correct host clock and seekbar, but they do not establish uninterrupted speaker playback on the current network link. Pause, stop, and skip still carry PCM pipeline latency because they act through the PCM path. Setting `hardware_volume=1` routes the volume slider directly to the speaker for lower-latency volume control.

## Hardware compatibility and validation

The only speaker physically validated here is **SPK-WAM550**, firmware `WAM550WWB-3117.1`. Shape M3/M7, WAM551, R1, and some Samsung Multiroom soundbars share API evidence, **not a successful WAM Bridge playback test**. A `SetUrlPlayback` success response cannot verify audible output, timing, controls, or model-specific volume scales.

The full M5 checklist passed on **2026-08-02**; a **2026-10-21** full-track recheck did **not** reproduce that stability on the then-current setup. Treat the earlier result as historical, not a current universal guarantee.

See the [model compatibility evidence and acceptance criteria](https://github.com/travnie/wambridge#speaker-compatibility) and the [latest physical status](https://github.com/travnie/wambridge/blob/main/foobar/README.md#physical-m5-checklist).

## Requirements

**CLI:**

- Python 3.14+
- FFmpeg available in `PATH`
- Computer and speaker on the same LAN
- Windows Firewall access for the bridge on private networks

**Foobar2000 component:**

- Windows 10/11 and foobar2000 2.x x64
- Computer and speaker on the same LAN
- A saved WAM device profile
- No separate Python or FFmpeg installation after the component is installed; its helper bundle includes what it needs
