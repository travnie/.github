Aistee provides local profiles, prompts, Library assets, and an explicit skills runtime. The portable [trvny/.ai](https://github.com/trvny/.ai) repository remains the canonical home for reusable cross-client profiles, instructions, and skills.

## Two different responsibilities

| Project | Owns |
| --- | --- |
| [Aistee](https://github.com/travnie/aistee) | Android/KMP client, local projects, provider sessions, profile editing, tool execution, and security UI |
| [trvny/.ai](https://github.com/trvny/.ai) | Portable reusable AI configuration, composition tools, schema, instructions, and skill definitions |

Copying the entire `.ai` tree into the app would create competing sources of truth. Portable assets should cross the boundary through an explicit import, pinned revision, or exported representation.

## Safety and portability

- Skills require explicit trust before sensitive operations.
- Provider web sessions, native API keys, and local project data are different storage and authorization domains.
- Keep private overlays, credentials, and machine-specific values outside the public `.ai` core.
- Treat file handling, imports/exports, and prompt-injection boundaries as product features, not incidental implementation details.

For implemented behavior and permission checks, use [Aistee skills runtime](https://github.com/travnie/aistee/blob/main/docs/skills-runtime.md). For portable profile composition, see [the .ai submodule guide](https://github.com/trvny/.ai/blob/main/docs/submodule.md).
